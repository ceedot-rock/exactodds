Provably fair is only half built.

Every "provably fair" casino today proves the outcome wasn't rigged: the house commits to a server seed, you supply a client seed, and the result is derived after the bet. That's real — but it's only half.

What none of them prove is the rules. The program that turned those seeds into your roll is a black box. A house can show one ruleset to an auditor and run another in production, and no amount of seed math will catch it.

ExactOdds closes the other half. Each game is one short program, compiled to byte-identical behavior on five runtimes — Python, JavaScript, TypeScript, C, C++ — or the compiler refuses it outright. Same seeds, same outcome, on every machine. The page below runs that exact program, locally, in your browser. Nothing you enter leaves this page.

How a player verifies any round

  1. Get the program. From this repository, or from the house's published copy. It's a few dozen lines — read the whole thing.
  2. Check the source hash. Run sha256sum on the file. It must equal the hash in the gate receipt and the hash the house published with its game listing. If it doesn't match, that's a different game — stop.
  3. Get the revealed seeds. After your round, the house reveals its server seed. Check SHA-256(server_seed) against the commitment it published before you bet. The box above does this in step 1.
  4. Re-run the round. Plug the revealed server seed, your client seed, and the round number into the program — any seat; the exactness gate guarantees they all agree. The output must match what the house reported for your round.
  5. Check the receipt. Each receipt records the gated verdict and per-seat results. An independent auditor re-runs gate/run-gate.sh and reproduces the same PASS.

Put this on your casino

If you run a casino and you market "provably fair", this is how you make it mean something:

  1. Publish the game's source hash and its gate receipt next to every game listing. Players hash the file and compare — that's the whole audit.
  2. Before each round, publish SHA-256(server_seed). After the round, reveal the seed. The verifier above checks the commitment in one click.
  3. Embed this verifier. It's a single HTML file — no server, no dependencies, no tracking. Your players check rounds without trusting you.
  4. Change the game, re-run the gate, publish the new receipt. Any source change changes the hash, so your players can tell the rules moved — and can verify the new ones the same way.

The pitch writes itself: every competitor proves the outcome. You prove the rules too. Same seeds, same outcome, on every machine — or the program is refused.

What ExactOdds is not.
